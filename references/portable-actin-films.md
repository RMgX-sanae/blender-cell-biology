# 独立重建 Arp2/3 与 formin 完整教学案例

`scripts/build_actin_films.py` 从公开结构重新准备资产、生成 21 个可编辑章节、渲染、编码并检查两条路线。输入是原始坐标和生成脚本，不需要旧 `.blend`、网格、视频、帧或原制作目录。两条路线仍采用 [actin-full-cycle.md](actin-full-cycle.md) 的特定教学综合情境；修改细胞、受体、亚型或机制时重新核对来源。

## 运行

准备 Python 依赖：`numpy scipy scikit-image gemmi fonttools Pillow`。Blender 使用自己的 Python。需要 Blender 5.x（当前实际测试版本为 5.2.3）和 FFmpeg。项目目录必须在 skill 外。

```bash
"$PYTHON" "$SKILL/scripts/build_actin_films.py" \
  --output "$PROJECT" --blender "$BLENDER" --ffmpeg "$FFMPEG" \
  --font-zh /installed/fonts/Songti-Regular.ttf \
  --font-en /installed/fonts/Times-New-Roman.ttf \
  --quality draft --steps prepare,build,render,encode,audit
```

中文默认宋体常规字重，英文和数字默认 Times New Roman 常规字重。macOS 可自动发现这两种系统字体，并将宋体集合中的指定字形提取到项目目录；其他平台传入实际安装路径。字体只打包进本地项目工程，不放进 skill 压缩包。

- `draft`：640×360、12 fps、8 samples，用于完整时序与技术检查。
- `review`：960×540、24 fps、16 samples，为默认档位。
- `final`：1600×900、24 fps、32 samples，仍需按实际画面增加采样。
- `--narration none` 为默认，保留可读主标签与独立 SRT，不插入自动旁白。`macos` 使用本机 `say` 与可选 `--voice`；`provided` 读取项目 `audio/<shot-id>.wav`。音频必须实际听检。无需旁白不代表删除机制阶段。
- `--engine eevee|cycles` 与 `--compositor clean|reference|monochrome` 独立选择。新滤镜叠加见 [render-recipes.md](render-recipes.md)。

可按 `prepare`、`build`、`render`、`encode`、`audit` 分步运行，后续调用从项目配置读取路径。`--shots a03,f04` 可定位章节；只有所有章节完成后才能合成整条路线。`--preview` 在构建时渲染三个关键时点。

## 可复现性与续跑

来源坐标逐份保存官方元数据和 SHA256；资产准备缓存检查输入及输出哈希。准备步骤中途失败的生成目录会改名保留，完整缓存才复用。来源或预处理变化时使用新项目目录。章节渲染按已保存工程的哈希分开缓存，完成的重复状态只渲染一次；重新执行 `render` 可补齐未生成的帧。编码用图像序列保持固定 fps，不用插帧填补缺失动作。

本入口重新计算链配准、G/F 示意形变、Rac/WRC 与 DID/DAD 接近方向和 FH2 动作参数。`prepare_contact_repairs.py` 还分别校正 CapZ 在 7TPT 与 9B27 丝端的完整刚体位置，并重算封端、去分支和 CAP 回收的局部路径。去分支采用整条子丝的小幅转向；不会靠拉伸蛋白、删除相撞原子或切开模型使检查通过。生成的 `assets/contact-repairs.json` 保存来源哈希、位置修正幅度、样条参数和检查距离；优化器的停止状态与几何检查结果分别记录。它不代表能量最优构象或实测解离轨迹。

不能把某个旧缓存 JSON 当作无法解释的固定真值。更新这部分代码后应重新执行 `prepare`，再构建受影响的 `a05,a07,c05,f06`。详细命令、返回码、日志和软件信息保存在项目 `validation/`。

`prepare_fh2_seed.py` 单独重算 `f03` 成核教学过渡。9B27 两条 FH2 链通过交叉的 lasso–post 接触组成二聚体；本例按一个链主体和伙伴的 lasso 分组，只利用来源中已经断开的未解析连接区。全部已有原子、顶点和面逐一保留，不切开表面，也不加入拉伸开门的形变。单体依次接近，一个结合单元暂时让位，再返回来源端部位置。来源仍是成熟丝端；这些早期动作不是实验观察到的成核中间体。

本成核章节中的 actin 保持 9B27 的 F 态参考几何；移动到游离位置并不会使它成为实测 G 态结构。本章用于解释装配关系，不包含 G→F 构象转变；需要讲解该变化时，应另用经来源核对的 G/F 状态与过渡检查。

未解析连接区以细曲线表示，与来源网格分开。重新打开保存工程后，逐帧检查曲线端点仍接在对应结构上、长度没有超过残基数给出的轮廓上限。这个上限只是几何约束，不证明无序链构象。曲线控制点也参与渲染缓存的状态哈希，避免仅曲线运动时错误复用静帧。成核的路径修正、原始网格归属和全场景采样结果写入项目 `assets/fh2-seed-repairs.json`。

`prepare_fh2_growth.py` 为 `f04/f07` 单独准备两轮延伸。它保留同样的完整结合单元，以伙伴在 9B27 中的构象作为另一个端点，重新计算丝端位置、小幅刚体转向和接近曲线。旧的整链弹性开门及其路径优化入口已移除。新的 G 态接触坐标优先使用 2BTF 中匹配原子的位置；未匹配原子和连续表面仍采用有记录的近似，不删除难以配准的部分。此资产只用于这两个章节，不会暗中改变其他章节的 G/F 模型。

供料、profilin 离开、单体加入和 FH2 换位一起检查，包括下一轮停靠前的单体、上一轮释放的 profilin、全部已有亚基及两侧结合单元。准备阶段使用 2001 个归一化时间点；另用明确的几何邻近半径检查是否出现两侧同时远离连通丝端。这个邻近检查不测量亲和力或成键。构建器在这些姿态之间插值，保存后仍按实际输出 fps 重新检查每帧，不能用准备阶段的采样替代成片检查。

`assets/fh2-growth.json` 保存匹配关系、来源哈希、修正参数、优化器状态和检查结果；`assets/fh2_growth/motion.npz` 是当前项目生成的姿态表，不随 skill 分发。连接曲线的锚点同时跟随构象和刚体运动。FH1 的供料作用用定时出现、指向 profilin 的图示箭头表示；不捏造未解析的 FH1 形状或原子级 FH1–profilin 结合构象。两轮的具体时序是教学编排；[mDia1/INF2 结构研究](https://doi.org/10.1038/s41586-024-07637-0) 和[另一套 formin 延伸机制研究](https://doi.org/10.1126/science.adn9560) 不提供这条逐帧动画的实验轨迹，不能把别的亚型加载状态直接当作 mDia1 中间体。

## 检查边界

`audit` 检查保存工程的完整基底网格、字体、全部时点变换、部分关键章节的原子中心严重重叠，以及实际 MP4 的帧数、时间基准、连续时间戳和图像尺寸。自动生成逐章视频抽帧图；agent 必须实际查看。接触诊断有警告时，应定位修正或明确记录，不能把“脚本退出成功”称为无穿插。

`audit` 会对已修正的 `a05,a07,c05,f03,f04,f06,f07` 自动执行 0.20 nm 全帧原子中心检查，未解决的重叠会返回失败，结果另存 `validation/strict-contacts-summary.json`，保留原有诊断汇总。也可单独执行：

```bash
BIO_FILM_PROJECT="$PROJECT" "$PYTHON" "$SKILL/scripts/actin_films/check_contacts.py" \
  --shots a05,a07,c05,f03,f04,f06,f07 --threshold .20 --fail-on-overlap
```

这仍只是所保存输出帧的几何检查，排除缺失原子、未建模配体和环境分子，不是分子力场计算。原有默认 0.12 nm 严重重叠诊断保留供旧案例比较；不能用降低阈值替代修正。部分章节构建后，接触检查只检查本次指定章节，不会要求未构建章节存在；网格和字体检查仍覆盖项目中已有的工程。

三维中没有穿插，也可能在相机投影中遮住下一步动作。检查释放后的伙伴是否挡住新配体的接近或落位；本例将离开的 FH2 二聚体继续移至右后方，完整保留在画面中。必要标签使用可读字号，机制限定、构建体说明和来源留在分镜、字幕及元数据中，避免叠加小字脚注。

逐章修正的通过结果不能概括尚未重新检查的整套影片。模板保留全部已建模链片段，没有删掉相撞原子来使检查通过。它是带明确简化的机制教学工程，不是分子动力学，也不宣称原子级连续催化轨迹。两条全周期计划的 `design_only` 描述计划本身；成片是否完成，以当前项目实际视频、检查与视觉记录为准。

交付留在项目目录。skill 只分发生成代码、参数、来源规则和说明。
