# 高效预览与产物保留

2026-11-06 用户要求提高效率，无须每次完整渲染视频，并授权持续清理渲染产生的大文件。默认按改动选择足以发现问题的检查，完成这些检查后继续任务，不重复未改变的工作。

## 按改动选检查

| 本次改动 | 先执行 |
|---|---|
| 来源、身份、单位、端态、路径 | 源数据与必要全部姿态的数值检查；这些检查不依赖逐帧渲染 |
| 构图、局部残基选择、材质、灯光、合成器 | 少量正式尺寸关键帧，覆盖最拥挤、最暗和变化后的状态；可复用仍有效的像素或已有 passes |
| 接近、转向、落位、释放、镜头运动 | 变化区间前后约 1–3 秒的低分辨率/低采样预览，按源时序播放 |
| 单帧可见性、拓扑切换、碰撞、闪烁 | 对相应短区间连续取帧；必要时使用最终采样与去噪设置，隔帧预览不能排除这些问题 |
| 完整视频交付、整片接缝/编码问题 | 最后才运行全部帧及完整编码检查；静态模型不因流程习惯而制作视频 |

关键时点由机制事件、接触最小值、标签切换、出入画等决定，不只等间隔取三张。已有源坐标检查通过而本次仅调整色板时，不重复下载来源或重算反应几何。变换、渲染引擎、合成器或依赖变更后，旧画面缓存不能作为新设置的检查证据。

## 已保存工程的关键帧与短预览

沿用 `render_saved.py`，`--frames` 可混合整数与包含两端的 `START:END[:STEP]` 范围，按时间排序并去重。例如 `1,193:195,613` 检查首态、中间切换及终态；`201:264:3` 实际输出 201、204、…、264。帧号必须依据项目事件选取，下列 PTP1B 帧号不适用于所有机制。

```bash
# 少量正式尺寸关键帧；保留保存工程的采样设置
"$BLENDER" -b "$PROJECT/scene/scene.blend" --python-exit-code 1 \
  --python "$SKILL/scripts/render_saved.py" -- \
  --directory "$PROJECT/review-stills" --frames 1,194,613 --width 1280

# 24 fps 源时间轴，每三帧取一帧：22 张图，原速预览 2.75 秒
"$BLENDER" -b "$PROJECT/scene/scene.blend" --python-exit-code 1 \
  --python "$SKILL/scripts/render_saved.py" -- \
  --directory "$PROJECT/review-departure" --frames 201:264:3 --width 640 --samples 8
"$PYTHON" "$SKILL/scripts/encode_review.py" "$PROJECT/review-departure" --ffmpeg "$FFMPEG"
```

宽度、采样和合成分支只在当前渲染进程修改，不重存 `.blend`。报告记录实际帧、源时间、采样和 fps_base；缓存指纹包括场景/脚本哈希、引擎、采样、尺寸与合成选择。`--resume` 只复用匹配且完整的 PNG；旧版指纹或设置不同则使用新目录。`--frames all` 保留完整渲染能力，兼容旧命令的默认值仍为 all，因此开发预览要显式给出取样范围。

`encode_review.py` 只接受一个等间距区间；用源 fps/fps_base 除以步长得到预览 fps，不插值或加速，最后一张保持一个采样间隔。不同步长、散乱分镜、EXR、损坏 PNG 或变更后的源工程会被拒绝。它输出 `review.mp4` 和包含源帧映射/限制的 `review.json`。不规则关键帧保留为静态图，不拼成貌似连续的动画。全片仍用 `encode_video.py`；短预览的检查记录不得标成完整成片验证。

## 工作单元结束后清理

优先清理已有成片及检查记录的逐帧 PNG、重复帧缓存、已被替代的试渲染。当前交付视频通常远小于其源帧，保留最新可展示版本和少量关键帧。旧 `.blend` 或准备缓存只有在生成方法、参数、来源及依赖均可复原且无后续引用时才清理；保留当前可编辑工程。不会自动删除用户提供的原始文件、唯一结构资产、字体、脚本、参数、来源及审查记录。

先生成具体文件清单，核对每个目录属于本任务并标明保留物；再按已授权范围执行，不进行无范围的磁盘清扫。删除前后核对保留物，记录路径、大小、删除数量与失败项。硬链接缓存的逻辑大小不能重复算成释放空间。检查记录中注明“中间帧已清理，可重建”，保留历史检查结果，但不继续声称所有原始帧仍在磁盘上。

有明确的持续清理授权时按此范围直接执行；其他用户或项目没有这项授权时，不将本项目授权外推。skill 包始终只含代码、参数和说明，所有预览与清理清单存于项目目录。
