# 从局部动作到完整机制

当用户要求“从上游到下游”“精确到全过程”时，先改变机制覆盖范围，再改善运动。单体接近、转向、落位只是延伸子模块；更慢、更漂亮的落位不能补上缺失的调控、成核、化学变化和回收。

## 明确可完成的生物学范围

写明细胞/物种、刺激、起始状态和结束状态。完整指**指定情境与边界内的因果链和物质循环**，不指所有细胞中所有已知调控因素。若用户尚未指定受体，提供有来源的上游接口，先完成共同机制；不要虚构一个通用受体—GEF—效应器通路。教学综合模型与某一种活细胞的实验重建分开标注。

覆盖检查使用以下维度，而不是视频秒数或对象数量：

| 维度 | 必须回答的问题 |
|---|---|
| 输入与定位 | 刺激在哪里被感知？通过何种受体/接头或已明确的调控边界到达执行器？蛋白在膜哪一侧？ |
| 开关与许可 | 哪个抑制被解除、哪个复合物被激活？需要哪些同时存在的条件？ |
| 原料准备 | 原料来自哪里、处于什么构象和化学状态、由谁携带或封存？ |
| 起始与延伸 | 初始成核/装配和已有结构上的继续生长有何不同？ |
| 化学状态 | 消耗、产物、离子与辅因子是什么？先后顺序和释放时点是否有独立依据？ |
| 功能输出 | 组装如何产生形态、运输、力或信号？哪些关系仅为示意？ |
| 终止与拆解 | 信号关闭、封端、解离、切断等分别发生在哪里？ |
| 回收与再进入 | 同一份材料如何回到可用池？是否真正闭合，还是偷偷用新对象替换？ |

## 建模前建立事件表

肌动蛋白示例见 [actin-full-cycle.md](actin-full-cycle.md) 和两套 JSON。每个事件写 `id / depends_on / actors / before / after / sources / implementation / checks`。`depends_on` 表示所选情境中的必要前提，**不是播放顺序**；镜头安排另列。复合物、亚基、核苷酸和释放产物分别保留 ID。记录跨膜、连接、聚合物归属、极性和配体状态的变化。

区分三类精度，不把它们互相代替：

- **结构精度**：实验坐标、装配、亚型、配体、缺失区、突变/融合体是否匹配。一个结构不自动包含上游状态或中间态。
- **机制精度**：事件与依赖有来源。来源只支持“同时需要”时，不写成已确定的固定先后；条件相关或竞争模型单独列明。
- **轨迹精度**：关键帧/插值通常是教学编排。两个静态结构之间的平滑形变不等于实验轨迹、能垒、真实速率或 MD。

## 分层制作，避免一镜头塞进所有过程

1. 总览镜头交代膜、胞质、细丝、极性和刺激；有必要时切到分子尺度，分别标比例。
2. 每次特写只解释一个事件；结合位点朝向、接触和释放各有清楚停顿。保留用户已认可的弧线接近、先转向再落位节奏。
3. 延伸至少展示两个可辨认循环。核苷酸反应、产物释放和回收用独立时间窗，避免暗示每次落位立即同步发生所有反应。
4. 返回总览展示局部事件如何形成网络功能；前、中、后景对象有身份与合理尺度。不能靠大量噪声增加“环境层次”。
5. 回收镜头跟随有标记的原亚基；用小范围身份提示维持连续性，不靠整体缩放、网格重置或瞬移闭合循环。

风格、引擎和合成器按项目选；全过程不要求统一写实风格。参考图决定材质、光、形体层次和构图，化学身份与拓扑不随风格变。内部观察仍采用完整单体的前后分层或整体隐藏，不把蛋白切开。

## 交付与验证分开

事件表覆盖通过 → 资产/状态匹配通过 → 实际保存工程通过 → 关键时点画面通过 → 整段导出视频检查通过。它们是不同结果。

`audit_mechanism_plan.py` 只检查两套肌动蛋白计划的字段、依赖和规定的化学闭环，不鉴定论文真假，不验证分子碰撞，也不证明动画已完成。计划为 `design_only` 时如实保留该状态；用户对局部运动的认可不等于对完整机制的认可。
